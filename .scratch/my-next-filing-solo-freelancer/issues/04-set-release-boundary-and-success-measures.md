# Set the successor release boundary and success measures

Type: grilling
Status: resolved
Blocked by: none

## Question

Which coherent user journey must the first successor release complete, which accepted capabilities belong in later slices of the same roadmap, and what observable evidence will show that the saved filing workspace is more useful than the current one-time check? Set the release boundary without assuming statutory support that research has not established, and define privacy-safe measures without sending Profile, money, result, or Completion record data to Analytics.

## Answer

### First successor release

Replace the current public journey only after the successor passes its statutory, privacy, stored-data migration, accessibility, browser, and release gates. Use deployment previews during development. Do not maintain a second public beta journey.

The successor release must complete this entire loop:

1. An eligible resident-individual solo freelancer with domestic or Foreign professional receipts enters or revises a Profile.
2. The Application returns the supported income-tax estimate, GST threshold status, and dated income-tax Obligations that verified Rules can establish.
3. The user explicitly opts into saving the Profile and Completion records on the current device.
4. A later reload or visit opens the saved filing workspace and shows the next incomplete Obligation without another questionnaire pass.
5. The user can mark an Obligation complete, undo that declaration, and see the remaining agenda update.
6. The user can delete the saved workspace and return the Application to its new-user state.

The income-tax expansion includes direct clients and freelance platforms, subject to the statutory Profile decision. It must support at least one verified foreign-client path and more than one common digital profession before public copy may describe the product as serving solo digital freelancers. If research supports a narrower group, the release must use the narrower audience name.

A GST-registered freelancer can receive a valid income-tax result while the Application returns Unavailable GST Coverage and clearly states that the GST-return calendar is not supported in this release, as settled in ticket 07.

A native share or copy-link action for the canonical public homepage may ship as optional finishing work. It cannot delay the saved-workspace loop and cannot contain personalized content or state.

### Later slices

After the first successor release:

1. Add the narrow GST-registered exporter calendar and Completion records for its supported Obligations.
2. Add Tax Year rollover and read-only archives before the next supported Tax Year requires them. This time-bound release moves ahead of the GST calendar if its statutory date arrives first.
3. Add another profession or platform path only when research establishes a distinct, reliable calculation path worth supporting.

### Success evidence

The primary product outcome is that a returning user can identify what remains without re-entering the Profile. Broader Supported-result coverage and initial questionnaire effort are guardrails, not competing primary outcomes.

Before release, test the complete loop with five representative solo freelancers. At least four must enter or revise a Profile, save it, reload, identify the next incomplete Obligation, mark it complete, undo the action, and delete the saved workspace without help. All five must understand that data is saved only on the current device and that a Completion record does not show government verification. The participants must collectively cover domestic clients, foreign clients, direct work, and platform-mediated work; one participant may cover more than one case.

Ticket 11 rejected all four candidate production events. This release has no product Analytics, observation window, or invented production success percentage. The moderated usability result is sufficient release evidence. Any future production measurement reopens the privacy, architecture, and success-measure decisions before implementation.
